# フロントエンド

React・TypeScript（strict）・Vite・Tailwind CSS。今は募集一覧（SCR-005）、募集詳細（SCR-006。未ログインと主催者の表示）、募集作成（SCR-007。作成だけ）、設定（SCR-015。ログアウトだけ）を実装している。**Supabaseには接続していない。**

## ブラウザで見る（Node.js 26系LTSがあるPC）

1. `frontend\start.cmd` をダブルクリックする（最初と、`package-lock.json` が変わったときは、部品の取得に時間がかかる）
2. ブラウザに募集一覧が開く。開かない場合は、黒い画面に出たアドレスを開く
3. 終了するときは、黒い画面で `Ctrl+C` を押す

## 準備（コマンドで行う場合）

```powershell
cd frontend
npm install
```

最初に実行したPCで `package-lock.json` ができるため、コミットする。2回目以降と、もう一方のPCでは `npm ci` を使う。

| コマンド         | 内容                                                                             |

| `npm run dev`    | 開発用の画面を開く                                                               |

## ダミーデータと開発用の帯

- 開発専用のダミーデータ・ログイン状態・開発用の帯は `src/dev/` だけに置く。架空の内容だけとし、実在の住所・連絡先・人や団体を入れない。住所は「ダミー住所A（架空）」「ダミー体育館A」のように、番地の形にしない
- 画面は `EventRepository`・`AuthRepository` を通してデータとログイン状態を取得する。ダミーは各機能の `repository.ts` が開発時にだけ動的に読み込み、すべての窓口が同じデータ（`src/dev/devRepositories.ts`）を共有する
- 画面から利用者のIDを渡さない。見ている人は、窓口が内部でログイン状態から決める。住所は `getLocation(eventId)` で別に取得し、許可されない人には `null` が返る
- 開発中は画面の上に「開発用の帯」が出る。未ログイン／利用者A（主に参加）／利用者B（主に主催）／18歳未満の利用者／プロフィール未登録の利用者を切り替えられる。ブラウザに保存しないため、再読み込みで未ログインとダミーデータの初期状態に戻る
- ログイン画面はまだ仮のもの。要ログインの画面を開くとログイン画面へ移るので、帯で利用者を選ぶと元の画面に戻る
- **開発用の窓口での判定（定員・18歳未満・作成の回数・住所の公開範囲など）は、画面の確認のためのもので、権限の確認にはならない。** 本番では、同じ条件をDB関数とRLSで強制する（docs/06の5章・6章）
- 本番用のビルドでは、ダミーデータも開発用の帯も読み込まれない。`src/dev/` の各ファイルは目印（`DEV-ONLY-DUMMY-DATA`）を含み、`npm run check:dist` でビルド結果に目印がないことを確かめる

Node.jsがないPCでは、ソースの編集だけを行い、上の確認はNode.jsがあるPCで行う（docs/08の9章）。
