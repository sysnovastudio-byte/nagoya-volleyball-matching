# 03 要件定義書

表記ルールは [01_企画概要](01_企画概要.md) を参照。機能ごとの詳細は [04_機能一覧](04_機能一覧.md) を参照。

## 1. システム概要

名古屋市内のバレーボールについて、主催者が募集を公開し、参加希望者が閲覧・質問・参加申請できるWebアプリ。主催者の承認によって参加が確定する。

## 2. サービスの目的【合意済み】

バレーボールをしたい参加者と、参加者を集めたい主催者をつなぐ。

## 3. 対象ユーザー【合意済み】

- 地域：名古屋市内
- 中心層：20代・30代の男女。年齢制限は設けず、他の年齢層も利用可能
- 経験：未経験者・初心者・経験者
- 参加形式：一人参加・友人同士の参加

## 4. 利用条件

| 条件 | 状態 |
|---|---|
| 募集の閲覧はログイン不要 | 【合意済み】 |
| 登録・ログインはメールアドレス＋パスワード方式。メール認証を行う | 【合意済み】 |
| 参加申請・承認・募集作成には利用者の識別が必要なため、ログインを必須とする | 【合意済み】の参加方式から導かれる前提 |
| チャットはログイン済みユーザーが利用できる | 【合意済み】 |
| ニックネームと経験レベルは必須 | 【合意済み】。入力タイミングは【未決定】Q-40 |
| メール未認証ユーザーの利用範囲 | 【未決定】Q-40 |
| 未成年者の利用条件 | 【未決定】Q-30 |
| 利用規約への同意 | 【未決定】Q-31 |

## 5. ユーザー種別と権限

主催者と参加者は固定のアカウント種別ではなく、**募集ごとの立場**として扱う【提案】。

| 操作 | 未ログイン | ログイン済み | 主催者（自分の募集） | 承認済み参加者 | 管理者 |
|---|:-:|:-:|:-:|:-:|:-:|
| 募集の公開情報を閲覧 | ○ | ○ | ○ | ○ | ○ |
| 詳細な開催場所・住所を閲覧 | × | × | ○ | ○ | Q-28 |
| 募集を作成 | × | ○ | － | ○ | － |
| 参加申請 | × | ○ | Q-13 | － | － |
| 申請の承認・却下 | × | × | ○ | × | × |
| 自分の参加をキャンセル | × | － | － | ○ | － |
| 主催者へのメッセージ送信 | × | ○ | － | ○ | － |
| 問い合わせへの返信 | × | × | ○ | × | × |
| ユーザー・募集・メッセージの通報 | × | ○ | ○ | ○ | － |
| ユーザーのブロック | × | ○ | ○ | ○ | － |
| 利用停止・解除 | × | × | × | × | ○ |
| 他人のメールアドレス・電話番号の閲覧 | × | × | × | × | Q-28 |

凡例：○ 可、× 不可、－ 該当しない、Q-xx 未決定。

- 主催者が自分の募集の住所を閲覧できる点は、主催者自身が入力する情報であるため前提とする。
- 通報・ブロックには操作者の識別が必要なため、ログインを前提とする【提案】。
- 管理者は一般ユーザーと同じ認証基盤を使い、管理者権限によって使える画面・操作を分ける【合意済み】。権限の付与方法は【未決定】Q-28。
- 利用停止中のユーザーはメッセージを送信できない【合意済み】。そのほかに制限する操作の範囲は【未決定】Q-28。

## 6. 機能要件

### 6-1. ユーザー登録・ログイン【合意済み】

- FR-01 メールアドレスとパスワードで登録・ログインできる
- FR-02 メール認証を行う
- FR-03 Googleログインは初期リリースでは実装しない

### 6-2. 募集の公開範囲【合意済み】

- FR-04 未ログインでも募集を閲覧できる
- FR-05 募集タイトル、開催日時、開催エリア、募集人数、参加費、主催者ニックネームを公開する
- FR-06 メールアドレス・電話番号は公開しない
- FR-07 詳細な開催場所・住所は参加承認されたユーザーだけに公開する
- FR-08 募集の閲覧と参加申請を区別する

上記以外の項目（残り枠数など）を未ログインユーザーに見せるかは【未決定】Q-24。

### 6-3. 参加方式【合意済み】

- FR-09 ユーザーは募集に参加申請できる
- FR-10 申請時に主催者へ通知する
- FR-11 主催者は申請を承認または却下できる
- FR-12 承認された場合に参加確定となる
- FR-13 定員を超える参加申請を防止する
- FR-14 同一募集への参加申請の重複を防止する

FR-13のうち、承認待ちの申請を定員に数えるかは【未決定】Q-13。どちらの場合も、**承認済み人数が定員を超えないこと**と、**満員の募集に申請できないこと**は必須とする。

### 6-4. キャンセル【合意済み】

- FR-15 参加者はいつでもキャンセルできる
- FR-16 キャンセル時に主催者へ通知する
- FR-17 キャンセル時に残り枠数を更新する
- FR-18 キャンセル履歴を保存する

無断欠席などへの対応は【未決定】Q-26。

### 6-5. チャット【合意済み】

- FR-19 ログイン済みユーザーは、参加申請前でも募集の主催者にメッセージを送信できる
- FR-20 募集の主催者と問い合わせユーザーの間でメッセージを送受信できる
- FR-21 ブロックした相手からのメッセージを拒否する
- FR-22 不適切なメッセージを通報できる
- FR-23 短時間の大量送信を制限する（具体的な数値は【未決定】Q-10）

### 6-6. 安全対策【合意済み】

- FR-24 ユーザーを通報できる
- FR-25 ユーザーをブロックできる
- FR-26 募集を通報できる
- FR-27 管理者はユーザーを利用停止できる
- FR-32 管理者はユーザーの利用停止を解除できる

メッセージの報告はFR-22に含む。FR-21〜FR-27とFR-32はすべて初期リリースに含む。管理者の操作は「通報管理」と「利用者管理」の2画面に分ける。利用停止と解除の条件は【未決定】Q-28。

### 6-7. プロフィール【合意済み】

- FR-28 次の項目を管理できる

| 項目 | 必須・任意 |
|---|---|
| ニックネーム | 必須 |
| プロフィール画像 | 任意 |
| 自己紹介 | 任意 |
| 経験レベル | 必須 |
| 年代 | 任意 |
| 性別 | 任意 |
| 活動地域 | 任意 |
| バレーボール歴 | 任意 |
| ポジション | 任意 |

- FR-29 メールアドレス・電話番号を他のユーザーに公開しない

項目ごとの公開範囲は【未決定】Q-18、選択肢や文字数は【未決定】Q-19。電話番号は管理項目に含まれていないため、**収集しない**設計とする【提案】。

### 6-8. 募集

- FR-30 ログイン済みユーザーは募集を作成できる【合意済み】（サービスの目的から必須）
- FR-31 募集を検索できる【提案】。検索条件は【未決定】Q-23
- 募集の編集・締切・中止は【未決定】Q-16

## 7. 非機能要件

数値目標は合意がないため設定しない（【未決定】Q-39）。

| 分類 | 方針【提案】 |
|---|---|
| 使いやすさ | 初めての人でも迷わず閲覧・申請できる画面にする |
| 性能 | 一覧はページ分割し、必要なデータだけを取得する |
| 整合性 | 定員・重複はデータベース側で保証し、同時操作でも崩れないようにする |
| 可用性 | 無料プランの一時停止・上限を把握したうえで運用する（[05](05_技術構成・開発環境.md)） |
| 保守性 | TypeScriptで型を付け、DB変更はマイグレーションで管理する |
| 拡張性 | 対象地域・通知手段・ログイン方式を後から追加しやすくする |
| アクセシビリティ | キーボード操作、ラベル、十分なコントラストに配慮する |
| バックアップ | Supabase無料プランには自動バックアップがないため、手段を別途決める（Q-05） |
| 費用 | 初期費用はできるだけ無料【合意済み】 |

## 8. セキュリティ要件

| No. | 要件 |
|---|---|
| SR-01 | 通信はHTTPSで行う |
| SR-02 | パスワードは認証基盤（推奨構成ではSupabase Auth）に任せ、アプリのテーブルに保存しない |
| SR-03 | 公開スキーマの全テーブルでRLSを有効にし、許可した操作だけを通す |
| SR-04 | 画面の表示制御だけに頼らず、データベース側でアクセスを拒否する |
| SR-05 | 詳細住所は公開情報と別テーブルに分け、主催者と承認済みユーザーだけが取得できる |
| SR-06 | 定員・重複・ブロック・送信回数の制限はサーバー側で強制する |
| SR-07 | 管理者権限と利用停止状態を、一般ユーザーが書き換えられないようにする |
| SR-08 | RLSを迂回できるシークレットキーをフロントエンドやGitHubに置かない |
| SR-09 | 利用者の入力はエスケープして表示し、XSSを防ぐ |
| SR-10 | 画像の形式と容量を制限し、本人の領域だけに保存を許可する |
| SR-11 | ログや通知に詳細住所・メールアドレスなどを不必要に含めない |

## 9. 個人情報の取り扱い

| 情報 | 取得 | 公開範囲 |
|---|---|---|
| メールアドレス | 登録に必要 | 他のユーザーに公開しない【合意済み】 |
| パスワード | 登録に必要 | 公開しない |
| 電話番号 | 収集しない【提案】 | 公開しない【合意済み】 |
| ニックネーム | 必須 | 主催者のものは未ログインにも公開【合意済み】。それ以外はQ-18 |
| プロフィール（ニックネーム以外） | 経験レベル必須、ほか任意 | 【未決定】Q-18 |
| 詳細な開催場所・住所 | 募集作成時 | 主催者と承認済みユーザーのみ【合意済み】 |
| メッセージ | チャット利用時 | 会話の当事者。通報された場合、管理者は対象のメッセージと対応に必要な範囲に限定して閲覧できる【合意済み】。具体的な範囲は【未決定】Q-28 |
| 通報・ブロック情報 | 操作時 | 通報は通報者と管理者、ブロックは本人のみ【提案】 |
| キャンセル履歴 | キャンセル時 | 【未決定】Q-26 |

- 保存期間・退会時の削除は【未決定】Q-27
- プライバシーポリシーは【未決定】Q-32
- 個人情報保護法、電気通信事業法、出会い系サイト規制法との関係は、公開前に専門家や所管官庁への確認が必要（Q-33〜Q-35）

## 10. 対応デバイス

- Webアプリとして提供する【合意済み】
- スマートフォンとPCのブラウザを対象とし、スマートフォンを優先して設計する【提案】
- 対応ブラウザ・バージョンは【未決定】Q-08（推奨構成のTailwind CSS v4は、公式にChrome 111・Safari 16.4・Firefox 128以降に依存するとしている）

## 12. 将来的な拡張方針【提案】

- ログイン方式・通知手段・対象地域は、後から追加できるように設定やコードを分離する
- 利用状況と意見を見て優先順位を決める
- 無料枠を超える前に、有料化・構成変更の判断を行う（Q-05）
